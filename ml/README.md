# MPLADS Machine Learning Anomaly Detection Module

This directory contains the machine learning anomaly detection engine for the MPLADS Fund Utilization and Risk Analytics Platform.

---

## 1. Objective & Ethical Disclaimer

> [!IMPORTANT]
> **Human Review Notice**: Flagged records generated by this module are statistical outliers (such as high fund expenditure velocity accompanied by low physical milestone completion). **They do NOT prove corruption, fraud, or wrongdoing.** Every flagged record is intended solely for administrative triage and must be reviewed and verified by an authorized human auditor or field inspection officer.

## 3. Algorithm: Isolation Forest

The anomaly detection engine uses **Isolation Forest** (`sklearn.ensemble.IsolationForest`), an unsupervised tree ensemble algorithm:
- Isolates anomalies by randomly selecting a feature and randomly selecting a split value between the maximum and minimum values of the selected feature.
- Because anomalies require fewer recursive partitions to isolate in feature space compared to normal observations, they receive significantly shorter path lengths.
- Scores are normalized into an intuitive `anomaly_score` ranging from `0.0` (normal) to `1.0` (highest audit priority).

### Engineered Features:
1. **`progress_discrepancy`**: Difference between financial progress (%) and physical progress (%). High positive values signify funds being drawn down while physical work lags.
2. **`exp_to_sanction_ratio`**: Ratio of total expenditure to initial administrative sanction (identifies cost overruns).
3. **`exp_to_release_ratio`**: Ratio of expenditure to released funds (measures drawdown velocity).
4. **`physical_progress_norm`**: Recorded physical completion rate (0% to 100%).
5. **`log_expenditure`**: Log-scaled expenditure amount to handle variance across small and large works.

## 4. Setup & Installation

### Step A: Create and Activate a Python Virtual Environment
Open PowerShell or your command prompt in the repository root:

```powershell
# Create virtual environment
python -m venv ml_env

# Activate on Windows (PowerShell)
.\ml_env\Scripts\Activate.ps1

# (Or in Command Prompt: .\ml_env\Scripts\activate.bat)
```

### Step B: Install Dependencies
```powershell
pip install -r ml/requirements.txt
```

---

## 5. Running the Anomaly Detector

### Running with Default Dataset:
```powershell
python ml/anomaly_detector.py --input data/sample_projects.csv --output data/flagged_projects.csv
```

### Configurable CLI Arguments:
| Argument | Type | Default | Description |
|---|---|---|---|
| `--input` | String | `data/sample_projects.csv` | Path to incoming project dataset CSV |
| `--output` | String | `data/flagged_projects.csv` | Destination path for flagged audit CSV |
| `--contamination` | Float | `0.15` | Expected proportion of outliers (0.0 to 0.5) |
| `--n_estimators` | Int | `100` | Number of trees in the forest |
| `--random_state` | Int | `42` | Random seed for deterministic reproducibility |

---

## 6. Output CSV Fields

The generated audit CSV includes the original project attributes alongside newly generated review columns:

| Column | Description |
|---|---|
| `anomaly_score` | Normalized score between `0.0` and `1.0` (higher = higher audit priority) |
| `is_flagged` | Boolean indicator (`True` if classified as an outlier, `False` otherwise) |
| `anomaly_label` | Human-readable label: `Flagged (Review Required)` or `Normal` |
| `progress_discrepancy` | Financial progress % minus physical progress % |
| `review_category` | Classification (e.g. *Progress-Disbursement Divergence*, *Unrevised Cost Variance*, *Stalled Physical Execution*) |
| `review_explanation` | Clear, plain-English summary explaining why the project was flagged |
| `audit_disclaimer` | Administrative reminder stating that the flag is for manual review and does not imply corruption |
